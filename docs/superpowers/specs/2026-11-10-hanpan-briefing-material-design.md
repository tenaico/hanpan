# AI 브리핑에 근거를 싣는다 (설계)

작성 2026-11-10. 대상: 트렌드 레이더(`tenaico/tenai-trend`, `/api/forecast`)와 한판(`apps/shell`의 트렌드 카드·AI 브리핑·`read_trend_forecast`).
싣는 판: 한판 0.19.3(AI 포토·일러스트 생김새와 함께). 트렌드 레이더는 그보다 먼저 배포한다.

## 1. 왜 하는가

한판의 AI 브리핑(0.19.1, 0.19.2에서 형식 선택)은 PC에 저장된 기상도(분야 10개의 날씨와 한 줄, 오늘의 한 줄)만 AI에 보내 헤드라인·현황·1~3개월 전망·체크포인트를 받는다. AI에게는 검색 도구가 없어서 전망은 AI의 추론이고 근거가 얇다.

저장소 주인이 고른 방향(2026-11-10, 공통 세션을 거쳐 전달, 이 세션에서 확인):
- AI에게 검색을 시키지 않는다.
- 트렌드 레이더가 분야별 핵심 수치와 기사 제목 두세 개(출처 링크 포함)를 기상도에 함께 싣고, 한판은 그것을 브리핑 질문에 넣어 근거로 쓰게 한다.
- 브리핑에 재료에 없는 숫자가 나오면 AI에게 한 번 다시 쓰게 하고, 그래도 남으면 그 문장을 뺀다.

## 2. 목표, 하지 않을 것, 실패로 볼 것

목표
- 기상도의 각 분야에 근거 재료가 붙는다: 핵심 수치, 정리된 요약 문장, 최근 기사 제목(언론사·날짜·링크).
- 브리핑이 그 재료를 근거로 쓰고, 문서 끝에 참고 자료(기사 링크, 자료 출처)가 붙는다.
- 브리핑 속 숫자가 재료에 있는 값인지 검사한다. 없는 숫자는 한 번 다시 쓰게 하고, 남으면 그 문장을 뺀다.
- AI 폴더 작업·외부 AI 프로그램이 쓰는 `read_trend_forecast`에도 같은 재료가 보인다.

하지 않을 것
- AI에게 웹 검색을 시키지 않는다.
- 기사 본문은 싣지 않는다(제목·언론사·날짜·링크만).
- 한판에서 밖으로 나가는 정보를 늘리지 않는다. 요청은 지금 그대로(`GET /api/forecast?client=hanpan&v=…`). 개인정보처리방침 트렌드 항목을 고치지 않는다.
- 트렌드 카드의 모양(분야 10개, 날씨, 오늘의 한 줄)은 바꾸지 않는다. 재료는 브리핑과 MCP 도구가 쓴다.

실패로 볼 것
- 새 칸이 없는 기상도(옛 서버 응답, PC에 저장된 옛 사본)에서 카드나 브리핑이 깨지는 것.
- 옛 한판(0.19.2 이하)이 새 응답 때문에 카드를 못 그리는 것.
- 재료를 만드는 원본(뉴스 등)이 실패해 기상도 전체가 늦거나 빠지는 것.
- 숫자 검사가 맞는 숫자를 틀렸다고 해 멀쩡한 문장을 지우는 일이 잦은 것.

## 3. 지금 상태 (확인한 것)

트렌드 레이더
- `/api/forecast`(`src/app/api/forecast/route.ts`)는 `loadForecastInputs()`로 원본(시세 `yahoo`, 한국은행 `ecos`, 허깅페이스 `hf`, 내 PC AI `localai`, 공포·탐욕 지수)을 모으고, 정리 자료 파일(`data/ai-big5.json`, `ai-safety.json`, `macro-outlook.json`, `semiconductor.json`)과 함께 `computeForecast()`로 분야 10개를 만든다. 응답은 `toForecastPayload()`의 schema 1. CDN에 30분 저장, 일부만 받으면 1분, 절반 넘게 비면 503.
- 정리 자료 파일에는 분야마다 헤드라인, 수치가 든 요약 항목 5~6개(한 항목 1~5문장, 73~265자), 출처 30~50개가 있고, 기준일 `asOf`는 파일 맨 위에 있다(AI Big 5, AI 보안·윤리, 경제·주식 `macro-outlook`, 반도체, 환율 `fx-outlook`, 부동산 `realestate`, 블록체인 `crypto`). 요약은 `overview.summary`에 있고, `macro-outlook.json`만 `economy.summary`와 `market.summary`로 나뉜다. 오픈소스 AI·내 PC AI는 정리 자료가 없고 허깅페이스 순위 수치만 있다.
- 뉴스는 구글 뉴스 RSS 검색(`src/lib/news.ts` `getNews(query, limit)`, 제목·링크·언론사·날짜, 15분 캐시)이고, 분야 화면마다 검색어가 있다(5.2 표).
- 배포: `trend.tenai.kr`은 팀 Vercel 프로젝트(`tenai-96329a4e/tenai-trend`)이고 `tenaico/tenai-trend`의 master에 저장소 주인 계정으로 합치면 자동으로 운영 배포된다. 대표님 계정 커밋은 팀 프로젝트가 막는다(배포 기록의 Blocked). 대표님 개인 배포(`tenai-trend.vercel.app`)는 한판과 무관하다.

한판
- `apps/shell/src/main/trend/trend-service.ts`가 시작 3초 뒤와 6시간마다 5초 안에 받아 `parseTrendForecast()`(`src/shared/trend-forecast.ts`)로 검사하고 `mergeTrendForecast()`로 이전 값과 합쳐 `userData/trend-forecast.json`에 저장한다. 검사는 알려진 칸만 골라 담으므로 모르는 칸은 버린다.
- 브리핑: `src/shared/trend-briefing.ts`의 `briefingPrompt(forecast)`가 분야마다 "제목: 날씨 — 한 줄"을 질문에 넣고, `TrendCard.tsx`가 AI 한 번(`runner`)을 부른 뒤 `parseBriefing`→`openBriefing({format, brief, forecast})`. 문서는 `briefingBlocks()`(0.19.2)로 Word·한글·마인드맵·PPT·PDF.
- 지시문은 "숫자는 기상도에 있는 값만"이라고만 하고 검사는 없다.
- MCP `read_trend_forecast`(`src/main/mcp/tools/trend-tools.ts`)는 저장본의 분야·날씨·한 줄·링크를 돌려준다.

## 5. 설계

### 5.1 기상도 형식 (schema 1 유지, 분야에 선택 칸 추가)

`fields[]`의 각 분야에 다음 칸을 **선택으로** 더한다. 없으면 지금과 같다. `schema`는 1로 둔다(옛 한판은 모르는 칸을 버리므로 그대로 동작).

```json
{
  "key": "stocks", "title": "주식", "scale": "weather", "s": -2, "label": "폭풍우",
  "head": "코스피 5,019 (-6.78%), 1개월 -26.2%", "path": "/stocks",
  "facts": [ { "label": "코스피", "value": "5,019 (-6.78%)" }, { "label": "코스피 1개월", "value": "-26.2%" } ],
  "points": [ "외국인 순매도가 9거래일째 이어졌다(10월 31일까지 누적 8.2조 원)." ],
  "news": [ { "title": "코스피 5000선 위태…외국인 매도 지속", "source": "연합뉴스", "date": "2026-11-09", "url": "https://news.google.com/rss/articles/…" } ],
  "materialAsOf": "2026-11-07"
}
```

- `facts`: 0~4개. 계산된 핵심 수치. `label` 20자, `value` 40자 이하.
- `points`: 0~3개. 정리 자료 파일 요약(`overview.summary`, 경제·주식은 `economy.summary`·`market.summary`)의 앞 항목들(분야에 정리 자료가 있을 때). 한 항목은 1~5문장(73~265자)이라 **자르지 않고 통째로** 싣는다. 300자를 넘는 항목은 건너뛰고 다음 항목을 본다(잘린 숫자가 생기지 않게). 정리 자료가 없는 분야(오픈소스 AI, 내 PC AI)는 비운다. 한판도 300자를 넘는 항목은 자르지 않고 버린다.
- `news`: 0~3개. 최근 30일 기사. `title` 120자, `source` 30자, `date` YYYY-MM-DD, `url`은 `https:`만, 1,000자 이하(11/10 실측 160~342자). 주소가 넘는 기사는 자르지 않고 버린다(잘린 주소는 열리지 않는다).
- `materialAsOf`: `points`를 뽑은 정리 자료 파일 맨 위의 `asOf`. 없으면 칸을 두지 않는다.
- 크기: 지금 응답은 약 2.6KB이고, 재료를 넣으면 약 25KB가 된다(11/10 실측: 요약 8개 분야 3항목씩 8.3KB, 기사 1건 평균 351바이트 × 30건 10.5KB, 수치 약 3KB). 서버는 응답이 64KB를 넘으면 기사, 요약 순서로 뺀다. 한판은 크기를 제한하지 않고 읽는다(`trend-ipc.ts`의 `res.json()`).

### 5.2 트렌드 레이더: 재료 만들기

- `computeForecast`가 이미 쓰는 입력에서 `facts`를 만든다(분야별로 지금 `head`에 쓰는 수치를 나눠 담는 수준). 새 원본을 부르지 않는다.
- `points`는 분야에 맞는 정리 자료 파일에서 뽑는다: AI Big 5 → `ai-big5.json`, AI 보안·윤리 → `ai-safety.json`, 경제 → `macro-outlook.json`의 `economy`, 반도체 → `semiconductor.json`, 환율 → `fx-outlook.json`, 부동산 → `realestate.json`, 블록체인 → `crypto.json`, 주식 → `macro-outlook.json`의 `market`.
- `news`는 분야 화면과 같은 검색어로 `getNews(q, 3)`을 부른다. 검색어를 화면 코드에서 공용 모듈로 옮겨 화면과 기상도가 같은 값을 쓴다.

| 분야 | 검색어 (지금 화면의 값) |
|---|---|
| AI 트렌드 Big 5 | `생성형 AI 챗봇 ChatGPT Claude Gemini` |
| 오픈소스 AI | `허깅페이스 오픈소스 AI 모델` |
| 내 PC AI | 화면에 없음 — 만드는 사람이 정해 공용 모듈에 적는다 |
| AI 보안·윤리 | 화면의 요약 탭 검색어(`Q.summary`) |
| 주식 | `코스피 증시 마감` |
| 경제 | `한국 경제 성장률 물가` |
| 반도체 | `반도체 HBM 메모리` |
| 부동산 | `아파트 매매 가격 동향` |
| 환율 | `원달러 환율 마감` |
| 블록체인 | `비트코인 가상자산` |

- 뉴스는 분야마다 따로 기다리고 실패하거나 5초가 지나면 그 분야만 `news`를 비운다. 뉴스 실패는 분야의 `known`(날씨 있음)과 503 판단에 들어가지 않는다.
- 응답 캐시 규칙(30분, 일부 1분, 503)은 그대로.

### 5.3 한판: 받기·검사·저장

- `parseTrendForecast`가 새 칸을 5.1의 상한대로 검사해 담는다: 개수는 앞에서부터 자르고, 글자는 `cutText`로 자르고, `url`이 `https:`가 아니거나 주소로 읽히지 않으면 그 기사를 버리고, 모양이 틀린 칸은 칸만 버린다(분야는 살린다).
- 옛 저장본·옛 응답(새 칸 없음)은 지금처럼 읽는다.
- `mergeTrendForecast`가 이전 값을 이어 쓰는 분야(R24: 새 응답에서 그 분야가 비었을 때)는 재료도 이전 것을 그대로 잇는다.
- 저장 파일 `trend-forecast.json`에 새 칸이 함께 저장된다.

### 5.4 브리핑 질문과 문서

- `briefingPrompt`가 분야마다 날씨·한 줄 아래에 재료를 붙인다: 수치(`라벨: 값`), 요약 문장(기준일 함께), 기사(`[n] 날짜 제목 — 언론사`). 기사 번호 `[n]`은 브리핑 전체에서 하나의 번호 체계다.
- 지시문(`BRIEFING_SYSTEM`)에 더한다: 재료에 있는 숫자와 사실만 쓴다, 기사 내용을 근거로 쓸 때 문장 끝에 `[n]`을 붙인다, 기사 제목에 없는 내용을 지어내지 않는다, 투자 권유 금지(그대로).
- 문서(`briefingBlocks`): 맨 끝 "자료" 줄 앞에 "참고 자료" 장을 더한다. 브리핑에 인용된 `[n]` 기사(제목·언론사·날짜·링크)와 정리 자료의 기준일을 적는다. 인용이 없으면 장을 두지 않는다.
- 링크: **Word·PDF는 누를 수 있는 링크**로 만든다(`DocBlock`에 링크를 담는 길과 docx·html 작성기를 넓힌다). **한글·PPT·마인드맵은 주소를 글자로 적는다**(한글·PPT 작성기에는 링크 기능이 없어, 넓히는 일은 이번 범위가 아니다). 설계자 판단, 0.19.3 크기 때문.

### 5.4.1 질문 크기 (로컬 AI)

AI 계정이 없는 사람은 PC의 로컬 AI가 기본이다(`local-ai-first.ts`). 로컬 모델은 문맥 창이 작을 수 있다(모르면 4,096 토큰으로 본다). 한판의 토큰 어림(`packages/agent-core/src/context-budget.ts`, 영문 4자·그 밖 1.5자당 1토큰)으로 11/10 자료를 재면, 지금 질문은 약 0.6K 토큰이고 재료를 다 넣으면 약 3.7K 토큰이다(수치 0.4K, 기사 30건 0.8K, 요약 24항목 1.9K). 4,096 창에서는 답할 자리가 남지 않고, 확인 창이 뜨는 선(창의 80%, 3,277)도 넘는다.

- 질문 예산 = min(문맥 창 − 답할 자리 1,024, 문맥 창 × 0.8). 4,096 창이면 3,072 토큰이다. 확인 창이 뜨지 않는다.
- 질문을 단계로 쌓는다: ① 분야별 날씨·한 줄·오늘의 한 줄(지금과 같음) ② 수치 ③ 기사 ④ 요약 문장. 예산 안에 들어갈 만큼만 단계를 더한다. 한 단계 안에서는 분야마다 첫 항목, 그다음 둘째 항목 순서로 돌아가며 넣고, 넘치면 거기서 멈춘다(한 분야가 재료를 다 차지하지 않게). 4,096 창에서는 ①~③ 전부와 요약 약 15항목이 들어간다(지시문이 약 0.1K 늘어난다고 보고).
- 기사를 요약보다 앞에 두는 까닭: 저장소 주인이 요청한 것은 핵심 수치와 기사이고, 기사 한 건(약 27토큰)이 요약 한 항목(약 80토큰)보다 작다. 요약을 앞에 두면 4,096 창에서 기사가 대부분 빠져 참고 자료 장이 빈다.
- 숫자 검사의 허용 숫자는 **실제로 보낸 재료**에서만 뽑는다.
- 다시 묻기는 질문 + 첫 답 + 고칠 숫자 목록이 문맥 창에 들어갈 때만 한다. 안 들어가면 바로 빼기 단계로 간다.
- 구독 AI(Claude·Codex)는 창이 커서 재료를 다 넣는다.

### 5.5 숫자 검사

- **검사 대상 숫자:** 브리핑의 헤드라인·현황·전망·체크포인트에서 숫자 덩어리(천 단위 쉼표·소수점·`%`·부호 포함)를 찾는다. 단, 다음은 검사하지 않는다: 기상도 날짜의 연·월·일, 1~12 사이의 정수 뒤에 `개월`·`월`·`분기`·`주`·`일`·`가지`·`개`·`위`가 오는 경우, 기사 번호 `[n]`.
- **허용 숫자:** 질문에 실제로 넣은 글(분야 제목·날씨·한 줄·`facts`·`points`·기사 제목·오늘의 한 줄 가운데 5.4.1에서 들어간 것)에 나오는 숫자. 쉼표와 `+` 부호를 떼고 같은 값이면 같다고 본다(`5,019` = `5019`, `+0.61%` = `0.61%`).
- **처리:** 허용되지 않은 숫자가 있으면 AI에게 한 번 다시 묻는다. 그 숫자 목록과 "재료에 있는 값으로 고치거나 그 문장을 빼고 같은 JSON 형식으로 다시"라는 요청을 붙인다. 다시 받은 브리핑에도 남으면 그 숫자가 든 항목(현황·전망·체크포인트의 한 줄)을 뺀다. 헤드라인에 남으면 헤드라인을 기상도의 오늘의 한 줄로 바꾼다. 항목을 뺐으면 문서의 "자료" 줄에 "재료로 확인되지 않은 숫자가 있던 문장 n개를 뺐습니다."를 붙인다.
- 다시 묻는 데 실패하면(AI 오류, 시간 초과) 첫 답으로 빼기 단계를 한다.
- 검사는 한판에서만 한다(`src/shared/trend-briefing.ts`의 순수 함수).

### 5.6 MCP `read_trend_forecast`

같은 재료를 돌려준다: 분야마다 `facts`, `points`, `news`(제목·언론사·날짜·링크), `materialAsOf`. 설명문에 "기사 제목과 정리 자료로만 근거를 삼고, 숫자는 여기 있는 값만 인용"을 더한다. 새로 받아 오는 것은 없다(저장본).

### 5.7 배포 순서와 담당

1. 트렌드 레이더: `tenaico/tenai-trend`에 PR → 테스트 → 저장소 주인 계정으로 합치면 `trend.tenai.kr`에 자동 배포. 옛 한판은 새 칸을 버리므로 한판보다 먼저 내도 된다.
2. 한판: 0.19.3에 싣는다(포토·일러스트 생김새와 함께). 판을 내기 전 실제 `trend.tenai.kr` 응답으로 브리핑을 확인한다.
담당: 둘 다 저장소 주인(병합·배포 판단), 구현은 Claude.

## 6. 확인 기준

- `trend.tenai.kr/api/forecast` 응답의 분야마다 `facts`, 정리 자료가 있는 분야의 `points`, 대부분 분야의 `news`가 있고 5.1 상한을 지킨다. 뉴스 원본을 막아도 기상도는 200으로 나온다(뉴스만 빔).
- 옛 형식 기상도와 옛 저장본으로 카드·브리핑·MCP가 지금처럼 동작한다(단위 테스트).
- 재료가 든 기상도로 만든 브리핑 문서에 참고 자료 장이 있다. Word·PDF에서는 인용된 기사 링크를 누르면 열리고, 한글·PPT·마인드맵에는 주소가 글자로 있다.
- 문맥 창 4,096 토큰으로 가정한 로컬 AI에서 질문이 예산 3,072 토큰 안에 들고 확인 창 없이 나가며, 기사가 분야마다 하나 이상 들어간다(단위 테스트로 단계 쌓기 확인).
- 숫자 검사: 재료에 없는 숫자가 든 답 → 다시 묻기 1회 → 남은 항목 삭제와 안내 문구(단위 테스트, e2e는 가짜 AI로).
- 한판이 보내는 요청 주소·머리글이 지금과 같다(기존 e2e).

## 7. 만드는 사람에게 맡기는 것

- 분야별 `facts`에 넣을 수치 고르기(지금 `head`의 수치를 기준으로, 분야당 4개 이하).
- 내 PC AI 뉴스 검색어.
- 숫자 덩어리를 찾는 정규식의 세부와, 예외 목록을 테스트로 고정하는 방법.
- 다시 묻는 질문의 문구.
- 마인드맵에서 링크를 담는 방식.

## 8. 위험

- 구글 뉴스 RSS는 이용 조건상 다른 서비스로 다시 내보내는 것이 사이트에 보여 주는 것보다 조심스럽다. 제목·언론사·날짜·링크만 싣고 본문은 싣지 않는다. 문제가 되면 `news`만 빼면 되도록 칸을 분리해 둔다.
- 기사 링크는 구글 뉴스 중계 주소다. 열면 원문으로 넘어간다.
- 숫자 검사가 반올림한 값("5천선")이나 단위를 바꾼 값을 틀렸다고 볼 수 있다. 다시 묻기 1회로 대부분 고쳐지고, 남으면 문장이 빠진다. 오탐이 잦으면 예외 규칙을 넓힌다.
- 응답이 커져 한판의 5초 안 받기가 느린 회선에서 실패할 수 있다(약 2.6KB → 약 25KB, 영향은 작다).
