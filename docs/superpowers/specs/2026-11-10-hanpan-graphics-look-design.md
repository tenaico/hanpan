# AI 포토·AI 일러스트를 한판의 생김새로 (설계)

작성 2026-11-10. 대상: `apps/graphics`(한판 쪽 탭)와 `tenaico/hanpan-graphics`(웹판 수정 패치).
관련 결정: 0093(웹판을 탭으로). 이 설계는 0093의 "앱 안의 PhotoCraft·VectorCraft 이름은 그대로 둔다"를 바꾼다.

## 1. 왜 하는가

워드·엑셀·한글 같은 한판 편집기는 켜면 한판의 일부로 보인다. AI 포토·AI 일러스트만 "한판 안에 다른 프로그램을 심어 놓은" 느낌이다(저장소 주인, 2026-11-10). 쓰는 방식이 아니라 **생김새**가 따로 논다: 색감(한판이 밝든 어둡든 어울리지 않음), 앱마다의 로고와 이름, 글꼴.

다른 편집기가 자연스러운 이유는 한 가지다. **같은 바탕·테두리·글자색과 같은 글꼴 위에, 앱마다 강조색 하나만 다르다**(`packages/ui/src/tokens.css`, 앱별 `--accent`). 두 그래픽 앱도 이 규칙 안에 들어오면 된다.

## 2. 목표, 하지 않을 것, 실패로 볼 것

목표

- 두 앱의 화면 틀(메뉴줄, 도구줄, 패널, 대화상자, 시작 화면, 상태줄)이 한판 편집기와 같은 바탕·테두리·글자색을 쓴다. 한판의 테마 설정(밝게·어둡게·시스템)을 따른다.
- 강조색은 앱마다 하나: AI 포토 `#A3449E`, AI 일러스트 `#3E9150`(홈 아이콘 색, PR #22).
- UI 글꼴이 한판과 같다(한국어 UI: Windows 맑은 고딕, Mac Apple SD 산돌고딕 Neo).
- 화면 틀에 PhotoCraft·VectorCraft 이름과 로고가 보이지 않는다.
- 탭 위의 빠른 작업 줄과 AI 도우미가 다른 편집기와 같은 모습이다(지금은 어둡게 고정).

하지 않을 것

- 메뉴 구조와 조작 방식은 바꾸지 않는다(포토샵식 메뉴줄은 그대로). 한판 리본으로 바꾸는 일은 이 설계 밖이다.
- 왼쪽 도구 아이콘은 다시 그리지 않는다(써 보고 걸리면 다음 설계).
- 그림 문서 내용(캔버스, 레이어 색)은 바꾸지 않는다. 화면 틀만 바꾼다.

실패로 볼 것

- 색은 바뀌었는데 일부 대화상자·팝업·메뉴가 원래 색으로 남아 섞여 보이는 것.
- 한판 테마를 바꿨는데 열려 있는 탭이 따라오지 않는 것(문서가 있는 탭 포함).
- 글꼴을 PC에서 못 불러온 경우 글자가 깨지거나 비는 것.
- AI 도우미, 빠른 작업, 저장, 기존 e2e·smoke 확인 중 하나라도 이전보다 나빠지는 것.

## 3. 지금 상태 (확인한 것)

- 한판 쪽 탭은 테마와 상관없이 어둡게 고정되어 있다: `apps/graphics/src/renderer/main.tsx`의 `applyTheme()`가 `data-theme='dark'`를 박는다(0.17 리뷰 G7, "앱이 어두우니 한 탭에 한 테마").
- 웹판은 `tenaico/hanpan-graphics`가 원본(`storytold/photocraft` v0.20.2, `storytold/vectorcraft` v0.21.0, MIT 또는 Apache-2.0)에 패치(포토 9개, 일러스트 7개)를 입혀 빌드한 것이다. 한판은 `tools/graphics-web-pins.json`으로 판(`-h6`)을 고정한다.
- 두 앱의 화면은 egui(Rust, 캔버스에 직접 그림)라 한판 CSS로는 바꿀 수 없다. 앱 코드(패치)로 바꾼다.
- 두 앱 모두 테마가 색 토큰 구조다.
  - 포토: `crates/ui-egui/src/theme.rs`의 `ThemeKind`(14종)와 `Tokens`(chrome, dock, card, field, text, text_dim, accent, separator, radius 등). 설정 `interface.appearance_mode`(auto/dark/light), `light_theme`, `dark_theme`.
  - 일러스트: `theme.rs`의 `Brightness`(4단계)·`Accent`(6색)·`Scheme`, `Tokens`(app_bar, panel, input, border, divider, text, accent 등), `apply_with()`.
- 글꼴: 일러스트는 한글에 NanumGothic(craft-fonts)을 쓴다. 두 앱 모두 PC 글꼴을 읽는 길(`0004-local-fonts.patch`, smoke `local-fonts` 확인 항목: 맑은 고딕을 불러와 한글을 내보냄)이 이미 있다.
- 한판이 앱 설정을 넣는 길도 이미 있다: 포토는 시작 전에 저장된 설정에 언어를 써 넣고(`frame/storage-prep.ts`), 일러스트는 페이지 API `prefs.set`을 부른다(`adapters/illust.ts`).
- 언어가 바뀌면 문서 없는 탭은 새 언어로 다시 시작하고, 문서가 있는 탭은 다음에 열 때 바뀐다고 알린다(G9, `App.tsx`).

## 5. 설계

### 5.1 한판 테마 (두 앱, 패치)

각 앱에 테마 둘을 더한다: **한판 밝게**, **한판 어둡게**. 기준은 표가 아니라 **AI 워드 탭이 실제로 그리는 색**이다. 값은 `packages/ui/src/tokens.css`와 워드 편집기(`apps/docs/src/renderer/styles.css`)에서 그대로 옮긴다.

| 역할                                 | 워드에서 같은 자리          | 밝게                           | 어둡게                                                   |
| ------------------------------------ | --------------------------- | ------------------------------ | -------------------------------------------------------- |
| 메뉴줄·도구줄                        | 리본 `--chrome-bg`          | #ffffff                        | #252525                                                  |
| 메뉴줄 아래 경계선                   | 리본 아래 `--border-strong` | #d9d9d9                        | #555555                                                  |
| 옆 패널(레이어·속성 등)              | 옆 창 `--surface`           | #ffffff                        | #1e1e1e                                                  |
| 한 단계 낮은 바탕(패널 머리, 입력칸) | `--surface-subtle`          | #f6f7f9                        | #2a2a2a                                                  |
| 캔버스 바깥(대지, pasteboard)        | 페이지 주변 `--canvas`      | #e6e6e6                        | #2b2b2b                                                  |
| 상태줄                               | 워드 상태줄                 | #f3f4f6                        | #252525                                                  |
| 테두리                               | `--border`                  | #e3e6ea                        | #3a3a3a                                                  |
| 구분선                               | `--border-subtle`           | #efefef                        | #3a3a3a                                                  |
| 글자                                 | `--text`                    | #242424                        | #e4e4e4                                                  |
| 보조 글자                            | `--text-secondary`          | #606366                        | #a0a0a0                                                  |
| 흐린 글자                            | `--text-tertiary`           | #909499                        | #a0a0a0                                                  |
| 마우스 올림                          | `--bg-hover`                | #f5f5f5                        | #333333                                                  |
| 누름·선택                            | `--bg-hover-strong`         | #e8eaee                        | #444444                                                  |
| 강조색                               | 앱별 `--accent`             | 포토 #A3449E, 일러스트 #3E9150 | 같은 색(어두운 바탕에서 읽히는지 확인, 필요하면 밝힌 값) |

- 대지는 회색(`--canvas`)이라 흰 그림판·사진의 가장자리가 보인다. 그림 자체의 색은 건드리지 않는다.
- 위 값이 워드 편집기의 실제 값과 다르면 워드 쪽 값을 따른다(목표는 나란히 놓았을 때 같아 보이는 것).
- 위 표에 없는 앱 토큰(눈금자, 가이드, 히스토그램, 그림자 등)은 만드는 사람이 정한다. 기준은 "가까운 역할의 한판 값, 없으면 원래 밝은·어두운 테마의 값"이다.
- 모서리 둥글기와 간격은 원래 테마 값을 둔다. 색과 글꼴만 바꾸는 것이 이번 범위다.
- 한판 안(embedded)에서는 이 테마만 쓴다. 앱 환경설정의 테마 선택은 감추거나, 바꿔도 한판 테마가 이긴다.

### 5.2 한판 테마 따라가기 (한판 쪽 + 패치)

- 두 앱의 embedded 패치에 페이지 API 명령 하나를 더한다: `hanpan.theme { mode: "light" | "dark" }`. 받으면 즉시 테마를 바꾼다(문서는 그대로).
- 한판 쪽 탭은 `graphicsApi().getTheme()`과 `onThemeChanged`로 한판 테마를 읽어, "시스템"은 `prefers-color-scheme`으로 풀어서 앱에 넘긴다.
  - 시작할 때: 앱이 첫 화면을 그리기 전에 넘긴다. 포토는 저장된 설정을 미리 써 넣는 길(`storage-prep.ts`)과 같은 방식으로, 일러스트도 같은 시점에. 첫 화면이 원래 색으로 깜빡이지 않아야 한다.
  - 바뀔 때: 열려 있는 모든 탭에 `hanpan.theme`을 보낸다. 언어와 달리 다시 시작하지 않는다.
- `main.tsx`의 어둡게 고정을 없애고, 탭 자체(빠른 작업 줄, AI 도우미, 대화상자)도 한판 테마를 따른다. 강조색 `--accent`는 앱 색(5.1)으로 둔다.
- AI 도우미가 `hanpan.theme`을 부를 수 없게 막는다(`blocked-commands.ts`).

### 5.3 글꼴 (패치)

- **바꾸는 것은 한글(과 한중일) 글꼴뿐이다.** 지금 두 앱은 한글을 NanumGothic으로 그린다. 이것을 한판 UI와 같은 PC 글꼴로 바꾼다: Windows 맑은 고딕, Mac Apple SD 산돌고딕 Neo. 다른 한중일 UI 언어는 한판 `--ui-cjk` 순서를 따른다.
- **라틴 글자와 숫자는 앱의 Inter를 그대로 둔다.** 워드는 라틴 글자를 Segoe UI로 그려 미세하게 다르지만, 두 앱의 패널 크기는 Inter에 맞춰져 있어(일러스트는 0.92배, 포토 패치 0009가 잘린 탭 이름을 고침) 바꾸면 모든 언어에서 배치를 다시 봐야 한다. 한국어 화면에서 눈에 띄는 차이는 한글이므로 이번에는 한글만 바꾼다(설계자 판단, 써 보고 라틴도 걸리면 다음에).
- 이미 있는 PC 글꼴 읽기 길(`0004-local-fonts`)로 불러온다. 못 불러오면(권한 거부, 글꼴 없음) 지금 글꼴(NanumGothic)로 그린다. 글자가 비거나 깨지면 안 된다.
- Mac은 베타이고 smoke가 Windows에서만 돈다. Mac에서 Apple SD 산돌고딕 Neo를 못 읽거나 늦으면 NanumGothic으로 그리는 것을 받아들인다. 핀을 올리기 전에 Mac 확인을 따로 하지 않는다(설계자 판단).
- 글자 크기는 원래 값을 둔다.

### 5.4 이름과 로고 (패치, 결정 변경)

- 메뉴줄·제목줄·시작 화면·상태줄에서 PhotoCraft·VectorCraft 이름과 로고를 뺀다.
- 시작 화면의 문구를 한판 말투로 바꾼다. 예: "VectorCraft에 오신 것을 환영합니다 / 벡터 일러스트레이션 — 빠르고 개방적이며 스크립트 지원" → "새 그림을 만들거나 파일을 여세요". 새 문서 크기 고르기, 끌어다 놓아 열기 같은 기능은 그대로 둔다.
- 도움말 › 정보(About)에는 원본 이름과 라이선스를 남긴다. `NOTICE.md`와 한판의 제3자 고지도 그대로다.
- **파일 형식 이름 `.vectorcraft`는 바꾸지 않는다.** 바꾸면 이미 저장된 파일과 복구 사본의 형식 이전이 필요하다. 대신 한판 쪽 저장·열기 대화상자의 형식 설명을 바꾼다(`graphics-main.ts`, `shell/main/index.ts`의 열기 필터, 21개 언어).

### 5.4.1 어도비 일러스트레이터 사용자를 위한 .ai (2026-11-10 저장소 주인 결정)

새 그림의 기본 저장은 `.vectorcraft`로 둔다. `.ai`로 저장하면 조건에 맞지 않는 살아 있는 효과·3D·원근 같은 편집 정보가 그림으로 굳는다(원본 README "reliable exchange of .ai files"). 대신 일러스트레이터 사용자가 헷갈리지 않게 .ai로 가는 길을 분명히 한다.

- 열어 둔 `.ai` 파일은 지금처럼 `.ai`로 다시 저장한다(바꾸지 않음).
- 새 그림의 저장 창 형식 이름은 쓰임새로 적는다: "AI 일러스트 문서 (.vectorcraft) — 한판에서 계속 고칠 때", "일러스트레이터 파일 (.ai) — 일러스트레이터와 주고받을 때, 일부 효과는 그림으로 굳음". 21개 언어.
- 탭 위 빠른 작업 줄에 "일러스트레이터용 .ai로 보내기"를 둔다(지금의 "PNG·SVG 내보내기" 옆). 지금 문서는 그대로 두고 `.ai` 사본을 저장 창으로 내보낸다. AI 일러스트 탭에만 있다.
- 새 그림을 처음 저장했을 때 한 번만 알린다: "AI 일러스트 문서로 저장했습니다. 일러스트레이터에서 열려면 '.ai로 보내기'를 쓰세요." 한 번 보면 다시 띄우지 않는다(설정에 기억).
- 기본 저장을 `.ai`로 하고 잃는 것이 있을 때만 묻는 안은 택하지 않았다: 잃는 것을 미리 아는 기능을 앱에 새로 넣어야 하고, 그 판단이 틀리면 되돌릴 수 없는 손실이 남는다.
- **AI 도우미의 지시문**(`base-photo.md`, `base-illust.md`)은 앱을 "AI 포토", "AI 일러스트"로 부른다. 그래야 AI의 답에 PhotoCraft·VectorCraft가 나오지 않는다. 명령 이름(`file.save` 등)은 그대로라 AI의 조작은 바뀌지 않는다.
- `hanpan-graphics` CI의 상표 검사(brand scan)에 "화면 틀에 PhotoCraft·VectorCraft가 남지 않음"을 더한다. 정보 창과 고지는 예외다.
- 0093의 "앱 안의 이름은 그대로 둔다"를 바꾸는 새 결정을 남긴다(번호는 다음 빈 번호).

### 5.5 빌드와 배포

- `tenaico/hanpan-graphics`: 포토·일러스트에 패치를 더하고(테마, 테마 명령, 글꼴, 이름·문구) `hanpanRev`를 7로 올린다. CI로 빌드한 초안 릴리스(`photo-v0.20.2-h7`, `illust-v0.21.0-h7`)를 README의 smoke 확인(Windows, GPU)을 거쳐 게시한다.
- smoke에 확인 항목을 더한다: `theme`(밝게·어둡게 명령 뒤 화면 틀 색이 한판 값인지), `font`(한국어 UI가 맑은 고딕인지, 못 불러올 때 대체 글꼴로 그려지는지).
- 한판: `tools/graphics-web-pins.json`을 `-h7`로 바꾸고, `apps/graphics` 변경과 함께 PR 하나로 올린다. 0.19.2는 다른 세션이 내므로, 이 작업은 그다음 판에 싣는다(판 번호는 그때 정한다).

## 6. 확인 기준 (끝났다고 볼 때)

- AI 워드 탭과 AI 포토·AI 일러스트 탭을 밝게·어둡게 각각 나란히 캡처했을 때, 메뉴줄·패널 바탕과 글자색과 글꼴이 같다. 강조색만 다르다.
- 화면 틀 어디에도 PhotoCraft·VectorCraft 이름과 로고가 없다(정보 창 제외).
- 한판 테마를 바꾸면, 문서가 열린 탭을 포함해 열려 있는 두 앱 탭이 1초 안에 따라 바뀐다.
- 기존 graphics e2e, 단위 테스트, hanpan-graphics smoke(README의 전 항목)와 새 항목(`theme`, `font`)이 통과한다.
- 그래픽 카드가 없는 PC의 안내(0.19.1)는 한판 테마를 따른다.

## 7. 만드는 사람에게 맡기는 것

- 5.1 표에 없는 앱 토큰의 값, 위젯 상태(눌림·비활성)별 세부 색.
- `hanpan.theme` 명령을 앱 안 어디에 꽂을지, 시작 전 설정을 넣는 정확한 열쇠 이름.
- 대체 글꼴 순서와, PC 글꼴을 불러오는 시점(첫 화면 전인지 직후 다시 그리는지). 단, 첫 화면 깜빡임은 없어야 한다.
- 시작 화면 문구의 다른 언어 번역(한판의 21개 언어 중 앱이 지원하는 언어).

## 8. 위험

- 원본 앱이 `theme.rs`를 크게 바꾸면 패치를 다시 맞춰야 한다. 테마 패치를 파일 하나에 모아 두어 충돌 범위를 줄인다.
- 브라우저의 PC 글꼴 읽기 권한이 막힌 환경에서는 글꼴만 대체된다(색과 이름은 그대로 맞음).
- egui의 글자 그리기는 Chromium과 미세하게 달라 픽셀까지 같지는 않다. "같은 글꼴, 같은 색"을 기준으로 본다.
