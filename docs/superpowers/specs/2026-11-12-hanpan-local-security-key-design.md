# 한판 로컬 보안키와 사용 동의 (설계)

작성 2026-11-12. 대상 판: 0.20.0. 대상: `apps/shell`(보안키·첫 실행), `packages/ai-provider`(AI 잠금), 설치 프로그램(electron-builder).
시안: https://claude.ai/artifact/V2RkvHm8Mm7yhSyX6EXik6 (저장소 주인 승인, 2026-11-12).
관련 결정: 0094(서버 보안키)를 이 설계로 대신한다. 새 결정 번호는 0099.
바탕 코드: 가지 `feat/security-key`(커밋 16개, main 350555c1에서 갈라짐, 푸시 안 함). 0094의 앱 쪽 구현이다.

## 1. 왜 하는가

2026-11-12 이사님 지시로 한판의 방향이 바뀌었다.

- 회원가입과 마케팅을 빼고, 누구나 바로 내려받아 쓰는 무료 오픈 프로젝트로 유지만 한다.
- tenai.kr 회원·보안키 서버(D)는 보류한다.
- 보안키는 앱 안에서 사용자가 USB를 꽂아 스스로 만든다.
- 문제가 생기면 사용자 책임이라는 약관을 설치할 때 보인다.

보안키가 지키는 것은 하나다. **한판에 직접 넣은 API 키를, 같은 PC를 쓰는 다른 사람이 못 쓰게 하는 것.** Claude·ChatGPT 구독 로그인은 각 회사 프로그램이 관리하므로 대상이 아니다. 보안키와 함께 받는 **사용 동의**는 무료 배포의 책임 범위를 분명히 한다.

## 출시 조건 (저장소 주인 결정, 2026-11-12)

- 0.20.0을 **2026-11-20**에 지금 문구(아래 5-6, 시안)로 낸다. 이사님·대표님 문구 확인을 기다리지 않는다.
- 확인 뒤 문구가 바뀌면 `termsVersion`을 올린 판을 낸다. 그러면 다음 실행에서 이용 조건(5-3의 1단계)만 다시 묻고, 보안키는 다시 만들지 않는다. 설치 프로그램 사용권은 새로 설치하는 사람에게만 바뀐 문구로 보인다.
- 예전 계획의 11/15 시연판(보안키 끈 빌드)은 서버 보안키 기준이라 두지 않는다. 시연은 0.19.5로 한다.
- 면책 문구에는 "TEN AI의 고의로 생긴 손해는 예외"만 둔다(저장소 주인 결정). 약관규제법 제7조상 중대한 과실 책임은 문구와 관계없이 남을 수 있다는 점을 문구 검토 때 함께 전한다.

## 2. 목표, 하지 않을 것, 실패로 볼 것

**목표**

1. 설치 프로그램(Windows NSIS, Mac dmg)이 사용권·면책 안내를 보여 주고, 동의해야 설치가 이어진다.
2. 모든 운영체제에서 첫 실행(새 설치와 0.19.x에서 업데이트한 뒤 처음 켤 때)에 이용 조건 요약에 동의해야 홈이 열린다.
3. Windows에서는 동의 다음에 보안키를 만들어야 홈이 열린다. USB(권장)나 이 PC 중에 고른다.
4. USB 보안키는 그 USB가 꽂혀 있어야 열리고, 쓰는 중에 빼면 잠긴다(0094와 같음).
5. API 키는 보안키의 vault로 잠근다(0094의 `sealed:v2:`). USB가 없으면 API 키는 열리지 않는다.
6. USB를 잃어버리면 "새 보안키 만들기"로 다시 시작한다. 문서와 설정은 남고, 잠가 둔 API 키는 지워진다.
7. "예비 USB 만들기"로 같은 보안키를 다른 USB에도 둔다.
8. 새 보안키가 만들어진 뒤 예전 USB를 꽂으면, 언제 새로 만들어졌는지 알린다.

**하지 않을 것**

- 서버, 회원, 온라인 확인, 폐기, 30일 오프라인 제한, 유예 날짜, 회원당 개수 제한.
- 구글 로그인, 복구 코드, Windows 비밀번호 확인.
- Mac·Linux 보안키(0094와 같음). Mac·Linux는 2번 동의만 한다.
- tenai.kr 쪽 변경.

**실패로 볼 것**

- 사용자가 USB를 잃어버리고 한판을 영영 못 여는 상태. "새로 만들기"가 반드시 열려 있어야 한다.
- 문구가 보안키가 지키지 못하는 것(구독 로그인, 문서 파일, PC 출입)을 지킨다고 읽히는 것.
- 보안키, 기기 번호, 동의 기록, 문서 내용, AI 대화를 TEN AI로 보내는 것. 이것들은 이 PC와 USB에만 둔다. 지금도 하는 두 가지 조회(홈 트렌드 카드의 trend.tenai.kr 기상도, GitHub 업데이트 확인)는 그대로 두고 사용권에 적는다(설계자 판단: 트렌드 카드는 0.19 홈의 핵심이고, 개인정보처리방침 1조 사에 이미 고지돼 있다).
- 자동 테스트(e2e)가 첫 실행 화면에 막히는 것.

## 3. 막지 못하는 것 (문서와 문구에 그대로 적는다)

- 같은 Windows 계정으로 PC 앞에 앉은 사람이 "새 보안키 만들기"를 누르면 한판이 열린다. 그 사람은 내 API 키를 쓰지 못하지만(지워짐), 내 문서 파일과 구독 로그인은 쓸 수 있다. PC 출입은 Windows 잠금이 막는다.
- 한판은 오픈소스라 확인 코드를 지운 빌드, 설정 폴더(`userData/securekey`)를 지우거나 고치는 것, 옛 판은 막지 못한다.
- USB 보안키 폴더를 다른 USB로 복사하면 기기 번호가 달라 열리지 않는다. 하지만 PC의 등록 기록을 고쳐 다른 USB를 넣는 것은 막지 못한다.

## 5. 설계

### 5-1. 파일

**USB** `<드라이브>:\Hanpan\`

- `hanpan.key`: `{ "v": 2, "keyId": "<무작위 16바이트 hex>", "createdAt": "<ISO>" }`. 서명 없음.
- `vault.key`: 무작위 32바이트(0094와 같음).

**PC** `userData/securekey/`

`registered.json`: 이 PC에 등록된 보안키. `where: "pc"`이면 `devices`는 비고, `pcConsentAt`이 있다.

```json
{
  "v": 2,
  "keyId": "…",
  "where": "usb",
  "devices": [{ "deviceId": "<디스크 일련번호의 SHA-256 hex>", "addedAt": "<ISO>" }],
  "createdAt": "<ISO>",
  "pcConsentAt": null,
  "previous": [{ "keyId": "…", "replacedAt": "<ISO>" }]
}
```

- `vault.key`: `where: "pc"`일 때만. Windows 봉인(DPAPI)한 vault.
- 이 파일은 운영체제 봉인을 하지 않는다. 고쳐도 vault가 없으면 API 키가 열리지 않기 때문이다.

**동의 기록** `userData/consent.json`: `{ "v": 1, "termsVersion": "2026-11-20", "acceptedAt": "<ISO>" }`. 모든 운영체제.

### 5-2. 켤 때의 판단 (Windows)

1. `consent.json`이 없거나 `termsVersion`이 빌드의 판과 다르면 → 첫 실행 창의 **이용 조건** 단계.
2. `registered.json`이 없으면 → 첫 실행 창의 **보안키 고르기** 단계.
3. `where: "pc"` → PC의 vault를 연다 → 홈.
4. `where: "usb"` → 꽂힌 USB마다 `Hanpan\hanpan.key`를 읽는다.
   - `keyId`가 같고 그 USB의 `deviceId`가 `devices`에 있으면 → vault를 연다 → 홈. 이후 그 USB를 감시한다(빼면 잠금, 0094와 같음).
   - `keyId`가 `previous`에 있는 USB만 있으면 → **"이 PC에서 보안키가 새로 만들어졌습니다 (날짜)"** 알림이 붙은 USB 기다리기 화면.
   - `keyId`는 같은데 `deviceId`가 목록에 없으면(폴더를 복사한 USB) → "등록하지 않은 USB입니다" 안내가 붙은 USB 기다리기 화면.
   - 아무 USB도 맞지 않으면 → **USB 기다리기** 화면. USB를 꽂으면 저절로 다시 판단한다.

Mac·Linux는 1번만 한다.

USB 목록 읽기는 0094의 `devices.ts`(PowerShell, 1~2초)를 쓴다. 등록하지 않은 PC에서는 USB 목록을 읽지 않는다.

### 5-3. 첫 실행 창 (시안 ②③)

한 창 안의 단계다. 0094의 `securekey.html` 등록 창을 고쳐 쓴다. 홈 창보다 먼저 뜨고, 마칠 때까지 홈을 열지 않는다.

1. **이용 조건**: 요약 4줄과 [전체 사용권 보기]. 동의 체크해야 [동의하고 계속].
2. **보안키 고르기**(Windows): USB(권장) / 이 PC. 아래에 두 줄을 적는다.
   - "Claude·ChatGPT 구독 로그인은 각 회사 프로그램이 따로 관리하며, 보안키와 관계없습니다."
   - "다른 사람이 이 PC를 쓰지 못하게 하려면 Windows 잠금을 함께 쓰세요."
3. **USB에 만들기**: 꽂힌 USB 목록에서 고른다. `Hanpan\` 폴더에 두 파일을 만들고 `registered.json`을 쓴다. 예비 USB 안내를 보인다.
4. **PC에 만들기**: 위험 안내와 책임 동의 체크. `pcConsentAt`을 남긴다.
5. 끝나면 기존 `sealed:v1:` API 키를 `sealed:v2:`로 바꾸고(0094와 같음) 홈을 연다.

### 5-4. USB 기다리기와 새로 만들기 (시안 ④⑤)

0094의 잠금 덮개·잠금 창을 쓴다. 덮개에 [새 보안키 만들기]를 단다. 누르면 이렇게 진행한다.

1. 확인 화면: 문서는 그대로, API 키는 지워져 다시 넣어야 함, 구독 로그인은 그대로, 예전 USB는 더는 못 씀. "API 키가 지워진다는 것을 이해했습니다" 체크.
2. 지금 `keyId`를 `previous`에 넣고 `registered.json`을 지운다.
3. `ai-settings.json`의 `sealed:v2:` 값을 모두 지운다.
4. 5-3의 보안키 고르기 단계로 간다.

예전 USB의 파일은 건드리지 않는다. 그 USB를 꽂으면 5-2의 "새로 만들어졌습니다" 알림이 뜬다.

### 5-5. 설정 › 보안키

홈의 설정에 칸 하나를 둔다. 0094에 있던 자리를 쓴다.

- 지금 보안키: USB(드라이브 이름)인지 이 PC인지, 만든 날.
- [예비 USB 만들기]: 지금 열려 있을 때만 쓸 수 있다. 다른 USB에 같은 두 파일을 쓰고 그 `deviceId`를 `devices`에 더한다.
- [USB로 옮기기] (PC일 때): 5-3의 3단계와 같다. PC의 vault는 지운다.
- [이 PC로 옮기기] (USB일 때): 위험 동의 뒤 vault를 PC에 봉인해 둔다. USB의 파일은 남긴다.
- [새 보안키 만들기]: 5-4와 같다.

### 5-6. 설치 프로그램 사용권 (시안 ①)

- Windows NSIS: electron-builder `nsis.license`. 한국어와 영어 두 판을 둔다. 설치 프로그램 언어에 맞춰 고르고, 그 밖의 언어는 영어를 보인다.
- Mac dmg: electron-builder의 dmg 사용권(같은 두 판).
- Linux: 설치 화면이 없어 5-3의 1단계만 한다.
- 본문은 시안 ①의 여섯 항목이다. 무료 오픈소스, 있는 그대로, 사용자 책임(TEN AI의 고의는 예외), AI 초안, 보안키 분실 시 복구 불가, 보내는 정보.
- 6항 "보내는 정보"는 이렇게 쓴다: "한판은 회원 정보, 문서 내용, AI와 나눈 대화, 보안키를 TEN AI로 보내지 않습니다. 홈 화면의 트렌드 카드는 trend.tenai.kr에서 기상도를 받아 오고, 새 판이 있는지 GitHub에서 확인합니다." 시안의 문구에 업데이트 확인을 더한 것이다.
- Apache License 2.0 원문은 붙이지 않는다(설계자 판단). 1항에 "라이선스 전문과 오픈소스 고지는 [정보]에서 볼 수 있습니다"라고 적고, 원문과 NOTICE는 지금처럼 앱에 함께 싣는다(`electron-builder.cjs`). 사용권 파일은 한국어·영어 두 개다.
- 같은 본문을 앱의 [정보] 창에서도 볼 수 있게 한다.
- 문구는 대외 약속이므로 이사님·대표님 확인을 받는다(혁준).

### 5-7. 바뀌지 않는 것 (0094에서 그대로)

- 잠긴 동안 AI 키 제공자 요청, 구독 프로그램 실행, 내 PC AI, 홈 검색 재정렬, MCP(423), 제어 채널(`app_unavailable`)을 막는다. `ai-settings.json` 쓰기도 거절한다.
- 열린 창과 문서는 닫지 않고 덮개를 씌운다.
- vault로 AES-256-GCM 뒤 DPAPI(`sealed:v2:`). 터미널 `--reveal-ai-secrets`도 USB가 없으면 열지 못한다.
- 등록 기록이 없는 PC에서는 아무 프로그램도 띄우지 않는다.

### 5-8. 지우는 것

- `format.ts`의 서명 형식·공개키·`verifySigned`, `status.ts`(서버 상태 확인, 30일), `register.ts`의 서버 활성화.
- 빌드 값 `__HANPAN_KEY_SERVER__`·`__HANPAN_KEY_PUBKEYS__`·`__HANPAN_KEY_REQUIRED_FROM__`, 유예 배너, `KEY_PAGE_URL`.
- `tools/securekey-dev-server.mjs`와 그 시험.
- 21개 언어 문구 중 회원·서버·유예 관련 줄.

`__HANPAN_REQUIRE_KEY__`는 남긴다. 정식 빌드에서 켜고, 개발 빌드와 e2e에서는 끈다(5-9).

### 5-9. 시험

- 단위: 5-2의 판단 표(모든 갈래), `registered.json` 읽기·쓰기(깨진 파일은 없는 것으로), 새로 만들기가 `sealed:v2:` 값을 지우는 것, 예비 USB가 `devices`에 더해지는 것, `consent.json` 판 비교. 기존 0094 시험 중 서버와 무관한 것(watch, lock-overlay, vault-codec, ai-lock 등)은 그대로 통과해야 한다.
- e2e: 기존 e2e는 동의와 보안키 없이 홈이 열려야 한다. 시험 환경 값 하나로 첫 실행 창을 건너뛴다. 새 e2e는 하나만 둔다. 임시 프로필에서 동의 → PC에 만들기 → 홈 → 설정에서 새로 만들기. 실제 USB가 필요한 갈래는 단위 시험의 가짜 USB 목록으로 확인한다.
- 사람이 하는 시험(혁준, USB 실물): USB에 만들기, 빼면 잠금, 다시 꽂기, 예비 USB, 잃어버린 셈 치고 새로 만들기, 예전 USB 알림.

## 6. 빌더에게 맡기는 것

- `feat/security-key`를 main(0.19.5)에 맞추는 방법(되감기 또는 새 가지로 옮기기). 충돌이 클 곳은 `apps/shell/src/main/index.ts`, `Home.tsx`, `ai-secrets.ts`다.
