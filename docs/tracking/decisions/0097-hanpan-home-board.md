# 0097 한판 홈은 카드를 끌어 놓는 보드이고, 트렌드 레이더의 기상도는 메인 프로세스가 받는다

## 맥락

0.18 홈에는 시작할 곳이 14군데(입력창 1개, 큰 카드 4개, 작은 버튼 9개) 있었다. 마인드맵만 세 번 나왔고, "AI 마크다운 + 변환기"처럼 버튼 두 개를 붙인 두 칸짜리 카드 때문에 줄이 들쭉날쭉했다. 거의 모든 버튼에 붙은 'AI' 표시는 정보가 되지 못했고, 하던 파일을 이어서 여는 곳은 맨 아래에 있었으며 최근 문서는 위젯과 표에 두 번 나왔다. 예시 칩은 이음오피스에서 물려받은 교사용 문구였다. 앱마다 버튼을 까는 구조라 앱이 늘면 홈도 계속 길어진다. 대표님의 트렌드 레이더(`trend.tenai.kr`)를 한판과 잇는 일(11/4 요청)과 가입자에게 트렌드 소식을 보내는 수익 구조(11/4 이사님안)를 보여 줄 자리도 없었다. 설계는 `docs/superpowers/specs/2026-11-09-hanpan-home-board-design.md`, 구현 계획은 `docs/superpowers/plans/2026-11-09-hanpan-home-board.md`다.

## 결정

- **홈 전체가 위젯 보드다(사용자 결정, 11/9).** 0.17 위젯의 '끌어서 옮기기'를 홈 전체로 넓혔다. 처음 켜면 카드 6장이다: 시작 7×2, 트렌드 5×2(화면 언어가 한국어이고 기상도 주소가 있을 때만), 새로 만들기 5×3, 이어서 하기 7×3, 빠른 메모 6×2, 즐겨찾기 6×2. 검색 칸과 '홈 꾸미기' 단추는 카드가 아니라 보드 맨 위 줄에 고정한다. 왼쪽 메뉴 맨 위에 '홈'을 두고, 전체 최근 목록은 '최근 사용'으로 옮겼다.
- **배치는 순서와 정해진 크기, CSS grid다.** 카드는 순서 목록에 있고, 크기는 카드 종류마다 허용된 몇 가지 중 하나다. 배치는 `grid-auto-flow: row dense`가 정한다. 넓은 화면은 12칸(세로 한 줄 96px, 칸 사이 14px), 홈 안쪽 넓이가 960px 미만이면 6칸, 700px 미만이면 1칸이고, 저장된 크기는 폭 때문에 바뀌지 않는다. 크기 모서리는 12칸일 때만 둔다.
- **새로 만들기 카드는 고정한 앱만 보이고, 나머지는 '모든 앱'에 있다.** 기본 핀 11개, 칸 수는 카드 크기로 정하고(5×3은 12칸), 마지막 핀 다음 칸이 '모든 앱'이다. '모든 앱'은 묶음별 목록, 검색, 최근에 쓴 앱 3개, 앱마다 핀 단추를 둔다. 새 앱을 핀에 자동으로 넣지 않는다.
- **저장은 `app-settings.json`의 `homeBoard`이고, 0.18 `homeLayout`은 읽기만 한다.** 0.18의 위젯, 메모 글, 앱 순서(`cardOrder`), 숨긴 앱(`hiddenCards`), 즐겨찾기에 고정한 앱(`pinnedApps`)을 옮겨 온다(계획 R2). `homeBoard`가 깨졌으면 없는 것으로 보고 `homeLayout`에서 다시 옮겨 온다(R3). 정리는 메인 프로세스가 읽을 때 하고 화면은 저장본이 온 뒤에 보드를 그린다(R4). 0.18로 되돌아가도 `homeLayout`이 그대로 남아 있다.
- **트렌드 레이더에 기상도 API를 더하고, 한판은 결과만 받는다(사용자 결정 A, 11/9).** 받는 쪽은 메인 프로세스다. 앱이 뜨고 3초 뒤와 켜져 있는 동안 6시간마다 받고, 5초가 넘으면 그만둔다. 보내는 것은 `?client=hanpan&v=<앱 버전>`과 `User-Agent: Hanpan/<버전>`뿐이고 쿠키를 보내지 않는다. 저장된 보드에 트렌드 카드가 있을 때만 받는다(R9, 카드를 빼는 것이 끄는 법이다). 응답은 형식을 검사해 맞지 않는 분야나 응답을 버리고(R11), 이전 저장본을 지우지 않는다. 화면 CSP(`connect-src`)는 넓히지 않고, 링크는 앱에 박아 둔 `https://trend.tenai.kr` 아래로만 연다.
- **카드 종류 이름은 한곳(21개 언어)에 둔다(R19).** '시작', '새로 만들기', '이어서 하기', '트렌드 레이더'는 홈 카드 제목이면서 홈 꾸미기의 카드 고르기와 목록 창에도 나오므로 `strings-home-custom.ts`에 둔다. 카드 몸통의 글(모든 앱, 트렌드 카드 글, 앱 한 줄 설명, 예시 칩)은 한판 홈 문구 11개 언어(`home-strings.json`)다.

## 택하지 않은 것

- **한 화면형(지금 뼈대 유지, 히어로 오른쪽에 트렌드).** 사용자가 시안에서 뺐다.
- **오른쪽 칸형(가운데 일하는 칸, 오른쪽 보는 칸).** Claude가 추천했지만 사용자가 위젯 보드형을 골랐다.
- **자유 배치 라이브러리(react-grid-layout 같은 것).** 아무 칸에나 놓을 수 있지만 의존성이 늘고, 화면 폭마다 배치를 따로 저장해야 해서 저장 형식과 옮겨 오기가 복잡해진다. 순서 + 정해진 크기는 카드 사이에 빈칸을 일부러 둘 수 없는 대신 화면 폭이 바뀌어도 순서만으로 다시 깔린다.
- **한판이 트렌드 레이더의 API 5개를 직접 불러 계산하기(B).** 계산 규칙을 한판에 복사하게 되어 사이트와 날씨가 어긋날 수 있고, 켤 때마다 요청이 5개씩 나간다.
- **정해진 시각마다 기상도를 파일로 만들어 두기(C).** 가장 튼튼하지만 예약 작업과 저장소가 따로 생긴다. A에 CDN 저장을 붙이면 효과가 거의 같다.
- **화면(렌더러)이 기상도를 직접 받기.** 화면 CSP를 바깥 주소로 넓혀야 한다. 메인 프로세스가 받으면 쿠키를 빼고 응답을 검사한 뒤 화면에는 IPC로 넘길 수 있다.

## 결과

- 홈에서 시작할 곳이 시작 카드와 새로 만들기 카드 두 곳이 된다. 앱이 늘어도 홈은 길어지지 않고 '모든 앱'이 늘어난다.
- 한판이 처음으로 바깥 주소에 스스로 요청을 보낸다. 받는 곳, 보내는 것, 저장하는 것, 끄는 법을 `docs/security.md`와 `PRIVACY.md`에 적었다. 사이트의 개인정보처리방침에도 같은 문구가 0.19.0 배포 전에 있어야 한다.
- 기상도에서 일부 분야만 계산된 답(`s: null`)이 오면 이전 저장본의 같은 분야 값(48시간 안)으로 채우고, 다른 날 값이면 그 분야에 날짜를 붙인다(R24, R25).
- e2e: 홈 선택자를 쓰던 시험 11개 파일을 새 보드에 맞췄다. 기본 핀에 없는 앱은 '모든 앱'을 거쳐 열고(`openFromAllApps`), 전체 최근 표를 쓰는 시험은 먼저 '최근 사용'으로 간다. 새 시험 `e2e/home-board.spec.ts`가 첫 실행 배치, 오프라인 트렌드 카드, 고정 기상도와 링크(`startTrendServer`), 핀, 목록 창의 키보드 이동, 0.18 옮겨 오기, 1366×728 창, 사용 설명서 단추와 F1, 머리 줄 검색을 본다. e2e는 기본으로 기상도 주소가 비어 있어 바깥에 요청하지 않는다.
- 판 번호는 0.19.0이다. 실제 기상도 주소가 열려 있어야 낸다. 보안키는 0.20.0으로 뒤에 낸다.
- 열린 문제: '홈에서 트렌드 소식 받기' 끄기 설정을 둘지(대표님, 11/17), 사이트 개인정보처리방침 문구(0.19.0 배포 전), 한국어가 아닌 화면에서 트렌드 카드를 기본에서 뺄지(지금은 뺀다, 11/17).
