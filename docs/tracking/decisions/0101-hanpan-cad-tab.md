# 0101 "AI 도면" 탭을 한판 저장소에서 새로 만들고, DWG·STEP 없이 낸다

## 맥락

대표님(Samuel)이 2026-11-15에 "뚝딱CAD 한판오피스 탑재 기획서"를 냈다. 따로 만든 뚝딱CAD v1(HTML 한 파일, 27.9MB)을 한판의 새 탭 "AI 도면"으로 넣자는 안이다. 기획서는 v1 코드를 한판 저장소로 옮기고, DWG(GPL-3.0)·STEP(LGPL-2.1) 엔진은 한판의 라이선스 허용 목록 때문에 빼고 시작하기로 정했다(2026-11-16).

v1 코드는 한판 저장소에도, 조직의 GitHub에도 없었다. 저장소 주인이 2026-11-16에 "v1을 옮기지 않고 기획서를 바탕으로 한판에서 새로 만든다"를 골랐다. 이사님의 11/13 지시는 "한판은 CAD까지 붙이고 동결"이다.

## 결정

- **AI 도면 탭은 마인드맵과 같은 모양의 편집기 모듈로 만든다.** 엔진은 `packages/cad-engine`(화면 없는 TypeScript), 화면·메인 프로세스·AI 창은 `apps/cad`다. 화면은 `genoffice-app://cad/`에서 열리고, 탭 종류는 `cad`다. 저장·닫기 확인·복구 사본(0061)은 다른 탭과 같은 규칙을 따른다.
- **v1 코드를 옮기지 않는다.** 3D 화면은 three.js(MIT), 입체 계산은 manifold-3d(Apache-2.0), 밑그림 삼각형 나누기는 earcut(ISC)로 새로 쓴다. 시험은 먼저 쓰고 구현한다.
- **manifold-3d는 3.2.1로 고정한다.** 3.3부터 명령줄 도구용 의존성이 딸려 오고, 그 안의 이미지 라이브러리(sharp)가 LGPL이라 `npm run licenses`가 실패한다(2026-11-16 확인). 입체 계산 기능은 3.2.1에도 있다.
- **`.ttukcad`는 한판용 새 형식이다.** UTF-8 JSON이고 `format: "hanpan-cad"`와 `version`을 품는다. 형식 이름이 없는 `.ttukcad`(단독판 파일)는 "아직 열 수 없다"고 알린다.
- **DWG·STEP·IGES·BREP는 읽지 않는다(기획서 방안 A).** 열려고 하면 "DXF나 STL로 받아 달라"는 안내를 보여 준다.
- **DXF·STL·OBJ·3MF·GLB·PLY는 읽기만 한다.** 그 파일을 열면 내용이 "제목 없는" 문서로 열리고, 저장은 `.ttukcad`로 따로 한다. 원본 파일에는 쓰지 않는다.
- **운영체제 파일 연결을 하지 않는다**(0093과 같은 이유). 탭은 홈 카드, "+" 메뉴, 파일 열기로 연다.
- **한 판에 모두 넣어 배포한다**(저장소 주인 결정, 2026-11-16). 엔진 → 탭 뼈대 → 편집 화면 → 치수·문서로 보내기 → AI → 21개 언어·도움말의 여섯 단계를 차례로 거치고, 단계마다 관문 시험을 통과해야 다음으로 간다.

## 택하지 않은 것

- **v1 코드를 받아 옮기기.** 코드가 저장소에 없었고, 저장소 주인이 새로 만들기를 골랐다. 옮겼다면 v1 시험 121개와 단독판과의 파일 호환을 그대로 얻었을 것이다.
- **그래픽 탭처럼 완전히 격리된 웹앱(0093).** 바깥에서 들인 코드를 가두는 방식이다. 우리가 쓰는 코드에는 창구만 늘고, 저장·복구 규칙을 다시 만들어야 한다.
- **디자인 보드처럼 별도 창.** 탭·복구·세션 기록을 쓰지 못한다.
- **두 번에 나눠 배포(받은 도면 보기 먼저).** 저장소 주인이 한 번에 내기를 골랐다.
- **manifold-3d 최신판과 라이선스 검사 예외.** 쓰지 않는 명령줄 도구 때문에 LGPL 패키지를 설치본 의존성 목록에 올리게 된다.

## 결과

- 단독판과 한판의 파일이 서로 열리지 않는다. 단독판 견본을 받으면 "가져오기"를 따로 더할지 정한다.
- 기획서의 "한판 코드가 단독판의 원본"은 이번에 정하지 않는다.
- 첫 단계(엔진)는 Node와 화면 양쪽에서 돈다. `tests/browser-safety.test.ts`가 Node 내장 모듈과 DOM을 막는다.
- 탭 하나를 더하려면 셸에서 60곳 넘게 고쳐야 한다(2026-11-16 조사). 형 검사가 잡아 주는 곳과 손으로 넣어야 하는 곳이 섞여 있다.

## 추가 결정 (2026-11-16, 3단계)

- **AI 도면 화면의 보안 정책(CSP)에 `'unsafe-eval'`을 넣는다.** 입체 계산기 manifold-3d 3.2.1이 시작할 때 `new Function`을 쓴다(embind). 이것이 막히면 실제 앱에서 도형이 하나도 계산되지 않는다(3단계 e2e에서 발견, `apps/cad/tests/csp-kernel.test.ts`로 재현). 화면은 원격 내용을 싣지 않고 `script-src 'self'`를 유지하므로 늘어나는 위험은 작다. 이 화면에 스크립트 주입 결함이 생기면 피해가 커지는 것이 비용이다. 더 엄격해야 하면 계산기를 Worker로 옮기는 별도 작업(며칠 규모)을 한다.
