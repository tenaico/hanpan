# 0100 Windows 설치 프로그램 첫 화면에서 언어를 고르고, 그 언어로 한판이 처음 켜진다

## 맥락

0092에 따라 한판은 설정에서 언어를 고른 적이 없으면 Windows 표시 언어를 따른다. 그런데 외국인이 한국어 Windows PC에 설치하면(예: 베트남 직원이 회사 PC에 설치) 설치 화면도 한판도 한국어로 열린다. Windows 표시 언어가 한판의 21개 언어에 없는 사람도 한국어를 본다. 설치 프로그램은 electron-builder의 기본값대로 여러 언어를 품고 있었지만 고르는 창이 없었고, 고른 언어가 앱으로 넘어가는 길도 없었다. 저장소 주인이 2026-11-16에 요청했다.

## 결정

- **설치 프로그램의 언어는 한판의 21개 언어다.** `electron-builder.cjs`의 `nsis.installerLanguages`에 English를 맨 앞에 두고 나열한다. Windows 표시 언어가 이 중에 없으면 설치 프로그램은 English로 열린다. 포르투갈어는 브라질·포르투갈 두 가지를 두고, 둘 다 한판의 `pt`가 된다.
- **언어 창은 처음 설치하거나 사람이 다시 설치할 때 한 번 뜬다.** Windows 표시 언어가 미리 골라져 있다. `build/installer.nsh`의 `customInit`이 `MUI_LANGDLL_DISPLAY`로 띄우고, 고른 언어 번호(Windows LANGID)를 `HKCU\Software\Hanpan`의 `InstallerLanguage`에 적는다.
- **업데이트(`--updated`), 조용한 설치(`/S`), 관리자 권한으로 다시 시작된 두 번째 실행에서는 창을 띄우지 않는다.** 대신 HKCU에 적힌 언어를 쓴다. 그래서 "모든 사용자" 설치에서 권한을 올린 뒤의 화면도 고른 언어로 이어진다. electron-builder의 `displayLanguageSelector`는 쓰지 않는다. 그 옵션은 업데이트 창과 두 번째 실행에서도 창을 띄운다.
- **설치하면서 고른 언어 번호를 `Hanpan.exe` 옆 `installer-language.txt`에 적는다.** 언어를 고른 적이 없으면(창도 HKCU 값도 없으면) 적지 않는다.
- **앱은 설정에서 언어를 고른 적이 없을 때 이 파일을 읽고, 읽은 언어를 설정에 저장한다.** 업데이트 설치는 설치 폴더를 지우고 새로 깔기 때문에, 저장해 두지 않으면 업데이트 뒤에 언어가 바뀔 수 있다. 판단은 `apps/shell/src/main/installer-lang.ts`(언어 번호를 한판 언어로)와 `index.ts`의 `currentLang`에서 한다.
- **우선순위는 설정에서 고른 언어 → 설치 때 고른 언어 → Windows 표시 언어(0092) 순이다.**
- 완전히 지울 때(업데이트가 아닐 때) HKCU 값을 지운다.
- **설정에서 고른 언어도 같은 HKCU 값에 적는다.** 앱이 켜질 때(설정에 언어가 저장돼 있으면)와 설정에서 언어를 바꿀 때 `reg.exe add`로 적는다. 그래서 "다시 시작 및 설치" 뒤의 설치 진행 창도 앱과 같은 언어로 뜬다. 적기에 실패하면 설치 창은 전에 적힌 언어로 뜰 뿐이다.
- **업데이트 창의 업데이트 내용은 한국어와 영어 두 부분으로 쓴다.** 릴리스 본문은 한국어, `---`, `## English` 제목, 영어 순서다. 앱(`update-notes.ts`의 `notesForLang`)은 한국어 화면에 제목 앞까지, 다른 20개 언어 화면에 제목 뒤를 보여 준다. 제목이 없는 본문(0.20.1까지의 릴리스)은 모든 화면에 전체를 보여 준다. 여러 판을 건너뛴 사람에게는 판마다 따로 나눈다.

## 택하지 않은 것

- **electron-builder의 `displayLanguageSelector: true` 한 줄.** 업데이트 창과 관리자 권한 두 번째 실행에서도 창이 뜨고, 고른 언어가 앱으로 넘어가지 않는다.
- **업데이트 내용을 21개 언어로 쓰기.** 판마다 20개 언어 번역과 검토가 필요하다. 영어는 대부분의 사용자가 읽을 수 있고, 21개 화면 언어 가운데 19개도 원어민 검토 없는 기계 번역이다.
- **업데이트 내용을 앱에서 기계 번역하기.** 번역을 위해 본문을 외부로 보내야 하고, 한판은 사용자가 고르지 않은 외부 전송을 하지 않는다.
- **앱 첫 실행에 언어 창.** 설치 화면(사용권 안내 포함)은 여전히 한국어로 보인다. 화면 하나를 21개 언어로 더 옮겨야 한다.
- **설치 언어를 레지스트리에서 앱이 직접 읽기.** 앱에서 레지스트리를 읽으려면 reg.exe를 띄우거나 네이티브 모듈이 필요하다. 설치 폴더의 글 파일 하나로 충분하다.
- **Windows 표시 언어가 한판에 없을 때 English로 바꾸기(0092 뒤집기).** 이번 요청 밖이고, 설치 창에서 English가 미리 골라지므로 Windows에서는 사실상 같은 효과가 난다.

## 결과

- 한국어 Windows에서 Tiếng Việt를 고르면 설치 다음 화면부터 베트남어로 나오고, 한판도 베트남어로 처음 켜진다. 시험용 설치 파일로 확인했다(2026-11-16, NSIS 3.0.4.1, 이 PC: 한국어 Windows 11). 언어 창은 한국어가 미리 골라진 채 떴고, 베트남어를 고른 뒤의 화면 단추는 "Đóng"이었다. 파일과 HKCU에는 1066이 적혔다.
- 한국어 Windows 사용자는 설치 때 OK를 한 번 더 누른다. 그 밖의 동작은 같고, 한판은 한국어로 저장된다.
- 이미 설치해 쓰던 사람은 업데이트 때 언어 창을 보지 않는다. 언어를 고른 적이 없으므로(HKCU 값 없음) 업데이트는 파일을 적지 않고, 한판은 지금처럼 0092 규칙을 따른다. 조용한 설치(`/S`)도 같다. 언어 창 없이 English를 적으면, Windows 표시 언어가 한판에 없어 지금 한국어로 쓰는 사람이 업데이트 뒤 영어를 보게 되기 때문이다.
- 시험용 설치 파일에 `installer.nsh`의 같은 조각을 넣어 네 경우를 확인했다: 아무것도 고르지 않은 조용한 설치와 업데이트(파일 없음), 전에 1066을 고른 뒤의 업데이트(1066), 언어 창에서 베트남어(1066).
- Mac(dmg), Linux는 설치 창이 없어 0092 그대로다.
- Windows CI는 HKCU에 1066을 적어 두고 설치 파일을 조용히 설치해, `installer-language.txt`에 1066이 적히는지 확인한다.
