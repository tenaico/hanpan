# 0099 한판은 이용 조건에 동의해야 켜지고, Windows판은 이 PC나 USB에 만든 보안키가 있어야 켜진다(0094를 대체)

## 맥락

0094는 tenai.kr 회원이 서버에서 받은 서명 보안키로 Windows판을 켜게 했다. 2026-11-12에 저장소 주인이 방향을 바꿨다. 한판은 회원가입 없이 누구나 내려받는 무료 오픈소스로 두고, 서버·회원·온라인 확인을 하지 않는다. 대신 처음 실행할 때 누구나 보안키를 만들게 하고, 사용권과 면책 안내에 동의받는다. 설계는 `docs/superpowers/specs/2026-11-12-hanpan-local-security-key-design.md`, 계획은 `docs/superpowers/plans/2026-11-12-hanpan-local-security-key.md`에 있다. 0.20.0(2026-11-20)에 낸다.

## 결정

- **이용 조건 동의는 모든 운영체제에서 받는다.** 첫 창보다 먼저 네 줄 요약에 동의해야 홈이 열린다. 동의는 데이터 폴더의 `consent.json`(`{ v: 1, termsVersion, acceptedAt }`)에만 남고 아무 데도 보내지 않는다. 문구가 바뀌면 `TERMS_VERSION`을 올려 다시 묻는다(보안키는 다시 만들지 않는다).
- **보안키는 앱이 혼자 만든다.** Windows판은 동의 다음에 보안키를 만들어야 홈이 열린다. USB(권장)나 이 PC 중에 고른다. 서명도 서버도 없다. 보안키는 무작위 키 번호(32자 hex)와 vault(무작위 32바이트)다. PC는 데이터 폴더의 `securekey\registered.json`에 키 번호와 등록한 USB의 기기 번호 해시를 적는다.
- **USB 보안키는 등록한 USB가 꽂혀 있어야 열린다.** 키 번호가 같고 기기 번호가 기록에 있는 USB만 받는다. 폴더를 다른 USB로 복사하면 "등록하지 않은 USB"로 잠근다. 쓰는 중에 빼면 0094처럼 잠그고 덮개를 띄운다.
- **PC 보관은 위험에 동의한 뒤에만 한다.** vault는 DPAPI로 봉인해 `securekey\vault.key`에 둔다. 같은 Windows 계정의 누구나 한판과 API 키를 쓸 수 있다는 것을 동의 칸으로 받는다.
- **잃어버리면 새로 만든다.** "새 보안키 만들기"는 잠금 화면과 설정에 있다. 문서와 설정은 남고, 예전 vault로 잠근 AI 키(`sealed:v2:`)는 지운다. 예전 키 번호는 `previous`에 남겨, 예전 USB를 꽂으면 언제 새로 만들어졌는지 알린다.
- **설정 › 일반 › 보안키**에서 예비 USB 만들기, USB와 PC 사이 옮기기, 새로 만들기를 한다.
- **설치 프로그램은 사용권과 면책 안내를 보인다.** `apps/shell/build/license_ko.txt`·`license_en.txt`(UTF-8, CRLF, BOM 없음. NSIS용 BOM은 electron-builder가 붙인다)를 NSIS와 dmg가 설치 언어에 맞춰 보인다. 같은 파일을 설정 › 정보와 첫 실행의 [전체 사용권 보기]에서 연다. 면책은 "TEN AI의 고의로 생긴 손해는 그러하지 않습니다"만 둔다(저장소 주인 결정).
- **0094에서 그대로인 것:** AI 키의 두 겹 잠금(vault로 AES-256-GCM 뒤 DPAPI, `sealed:v2:`), 잠긴 동안 AI와 바깥 창구 막기, 덮개, Mac·Linux에는 보안키가 없음, 등록 기록이 없는 PC에서는 아무 프로그램도 띄우지 않음, 빌드 값 `HANPAN_REQUIRE_KEY`(정식 빌드에서 켬, 개발 빌드와 e2e에서 끔).

## 택하지 않은 것

- **0094의 서버 서명과 회원당 3개.** 회원가입을 없앴으므로 서명할 주체가 없다.
- **Google 로그인.** 구독 AI처럼 계정에 묶는 편은 간편하지만, 회원 정보를 다루지 않는다는 방향과 맞지 않는다.
- **복구 코드, Windows 비밀번호 확인.** 같은 PC 앞의 사람을 막지 못하는 점은 같고, 단계만 늘어난다.
- **면책 문구의 "중대한 과실" 예외.** 저장소 주인이 뺐다. 약관규제법 제7조상 중대한 과실 책임은 문구와 관계없이 남을 수 있다는 점은 문구 검토 때 함께 전한다.

## 결과

- 같은 Windows 계정으로 PC 앞에 앉은 사람이 "새 보안키 만들기"를 누르면 한판이 열린다. 그 사람은 내 API 키를 쓰지 못하지만(지워짐), 내 문서 파일과 구독 로그인은 쓸 수 있다. PC 출입은 Windows 잠금이 막는다.
- 확인 코드를 지운 빌드, 데이터 폴더의 `securekey` 기록을 지우거나 고치는 것, 옛 판, Mac·Linux판, 터미널 명령은 막지 못한다.
- 서버가 없으므로 서버가 멈춰 모두가 잠기는 일도 없다. 30일 오프라인 제한과 유예 날짜가 없어졌다.
- `tools/securekey-dev-server.mjs`, 서명 형식, 서버 상태 확인, 유예 배너를 지웠다.
